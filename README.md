# Gold 상관관계 대시보드

금(Gold) 가격과 상관관계가 있는 5개 지표(실질금리, 달러인덱스, 금/은비율, WTI, VIX)를
한 화면에서 확인하는 Streamlit 대시보드입니다.

## 구성

- `gold_dashboard/config.py` — 지표별 구조/의미/상관관계 방향(고정 텍스트)과 출처 각주
- `gold_dashboard/data_sources.py` — FRED 공식 API 및 yfinance 데이터 수집 (재시도/백오프 포함)
- `gold_dashboard/metrics.py` — 5/30/60일 이동평균 및 "돌파지속 일수" 계산
- `gold_dashboard/build_table.py` — 지표별 데이터 수집 + 계산 결과를 하나의 표로 조립
- `gold_dashboard/update_data.py` — `data/latest.json`을 생성하는 CLI 스크립트
- `gold_dashboard/timeseries.py` — 시계열 fetch 공통 모듈 (백테스트와 메인 페이지 그래프가 함께
  사용). 모든 fetch 함수가 `years` 인자를 받아, 백테스트 페이지의 조정 가능한 분석 기간과
  메인 대시보드의 고정 기간이 서로 영향을 주지 않도록 분리되어 있습니다.
- `gold_dashboard/backtest.py` — 신호 기반 매매 전략 백테스트 로직(데이터 정렬, 신호 계산, 매매 상태 머신, 성과 지표)
- `app.py` — Streamlit 대시보드 화면. `st.navigation`/`st.Page`로 진입점을 구성해서, 사이드바에
  보이는 페이지 이름(대시보드/유효성 검증)을 실제 파일명·URL 경로와 분리해뒀습니다 — 파일명과
  기존에 공유된 URL(`/`, `/백테스트`)은 그대로 유지됩니다.
- `pages/1_백테스트.py` — 백테스트 결과 페이지(사이드바에는 "유효성 검증"으로 표시, 파일명과
  URL 경로(`/백테스트`)는 이전과 동일)
- `.github/workflows/update_dashboard_data.yml` — 매일 07:00(KST)에 데이터를 자동 갱신하는 GitHub Actions 워크플로우

## 백테스트

사이드바의 "유효성 검증" 페이지(파일명은 `pages/1_백테스트.py`, URL은 `/백테스트`로 이전과 동일)에서
실질금리·달러인덱스 이평선 돌파 신호(green_count, 대시보드의
"금값에 우호적인 방향" 판정과 동일한 로직)와 금/은비율 임계값, 재진입 조건(아래 참고)을
결합한 매매 전략을 분석 기간(이동평균 계산용 버퍼 400캘린더일 추가 — 재진입 조건의 200일
이동평균을 분석 기간 첫날부터 완전히 계산할 수 있도록 충분히 크게 잡음) 동안 시뮬레이션하고,
동일 시작일의 Buy & Hold와 비교합니다.

**분석 기간**은 "분석 기간 (최근 N년)" 입력으로 3~10년 사이에서 조정 가능하며 최초 접근 시
기본값은 7년입니다. 이 값은 `st.session_state["bt_years"]`로 이 페이지 안에서만 관리되는
완전히 독립된 상태값이라, 바꿔도 이 페이지의 결과(거래 내역·승률·CAGR·그래프)에만 영향을
주고 메인 대시보드에는 전혀 영향을 주지 않습니다 — 메인 대시보드의 지표별 그래프는 이 값과
무관하게 항상 고정 10년치 데이터로 그려집니다.

화면은 **매수 조건 / 매도 조건 두 카드**로 나뉘어 있고, 각 카드에는 자주 조정하는 핵심 값만
보입니다 — 지연일수·최소 보유일수·단기 재진입 빈도 제한처럼 기본값을 그대로 쓰는 경우가 많은
설정은 "⚙️ 고급 설정" 접기 안에 매수/매도로 나눠 정리되어 있습니다. 우측 상단의
"↺ 기본값으로 초기화" 버튼으로 모든 값을 한 번에 원래대로 되돌릴 수 있습니다. 요약 지표
(연환산수익률 등)는 조건 설정 바로 아래, 차트보다 먼저 표시되어 값을 바꿔가며 시뮬레이션하기
편합니다.

- **매수** (미보유 시): `green_count ≥ 매수 카드에서 설정한 값(기본 6)` (실질금리+달러인덱스 ×
  5/30/60일, 총 6개 셀 중 우호적인 셀 수) — 매수 지연일수만큼 지난 뒤 체결. **또는**
  `금/은비율 ≥ 매수 카드에서 설정한 값(기본 100)` — 메인 대시보드 그래프의 매수신호 음영
  임계값과 같은 상수(`config.DEFAULT_GS_RATIO_BUY_THRESHOLD`)를 공유하며, 지연 없이 항상
  당일 종가에 즉시 체결. **또는** (고급 설정의 **단기 재진입 로직 사용**이 켜져 있을 때만)
  **재진입 조건**: ① 장기추세 필터(필요조건, **아래 두 가지를 모두** 만족해야 함) — 금(GC=F)
  종가가 200일 이동평균보다 "① 장기추세 필터 버퍼(%)"(기본 5%, 조정 가능) 이상 높고, 그리고
  200일 이동평균 자체가 20거래일 전보다 높음(우상향 중 — 종가가 버퍼를 넘더라도 200일선이
  꺾여 내려가는 중이면 필터를 통과하지 못함). 동시에 ② 단기 재돌파 트리거 — 금 종가가 20일
  이동평균을 아래에서 위로 상향 돌파한 날. 이것도 지연 없이 즉시 체결. 금/은비율·재진입은
  아직 대기 중인 green_count 지연 매수 주문이 있어도 우선 체결됨
- 고급 설정의 재진입 관련 설정은 **2단계 구조**입니다:
  - **단기 재진입 로직 사용** (기본값 켜짐) — 끄면 재진입 조건(①②) 자체를 전혀 적용하지
    않고, 이 로직 도입 이전의 재진입 기준(green_count·금/은비율만)으로 되돌아갑니다. 켜져
    있을 때만 아래 "① 장기추세 필터 버퍼 (%)" 입력과 "단기 재진입 빈도 제한" 체크박스가
    활성화됩니다(꺼져 있으면 둘 다 비활성화되어 표시만 되고 값과 무관하게 작동하지 않음)
  - **① 장기추세 필터 버퍼 (%)** (기본값 5%) — 버퍼 %가 클수록 필터가 더 엄격해져 재진입
    트리거 발생 빈도가 줄어듭니다(모노토닉: 버퍼를 0%에서 올릴수록 트리거 횟수는 감소하거나
    같습니다). 200일 이동평균의 우상향 조건(20거래일 전보다 높음)은 이 값과 무관하게 항상
    함께 적용됨
  - **단기 재진입 빈도 제한** (기본값 켜짐, 상위가 켜져 있을 때만 작동) — 켜두면 ② 단기
    재돌파 트리거로 인한 매수만 최근 "단기 재진입 빈도 제한 일수"(기본값 30일, 역일 기준,
    사용자가 직접 조정 가능) 내 최대 1회로 제한되며(① 장기추세 필터는 이 제한과 무관하게
    항상 필요조건), 끄면 제한 없이 자유롭게 재진입
  - 세 설정 모두 상태 변경 시 요약 지표 전체가 즉시 재계산됩니다. 버퍼 %는 이미 계산된
    200일 이동평균 값에 대한 비교 임계값만 바꾸는 것이라 별도의 이동평균 재계산이나 데이터
    재수집 없이 즉시 반영됩니다(`gold_dashboard/backtest.py`의 `compute_reentry_trigger`)
- **매도** (보유 시): `green_count ≤ 매도 카드에서 설정한 값(기본 0)` — 매도 지연일수만큼
  지난 뒤 체결. **또는** `금/은비율 ≤ 매도 카드에서 설정한 값(기본 60)` — 메인 대시보드
  그래프의 매도신호 기준선과 같은 상수(`config.DEFAULT_GS_RATIO_SELL_THRESHOLD`)를 공유하며,
  지연 없이 항상 당일 종가에 즉시 체결(마찬가지로 대기 중인 green_count 지연 매도 주문을 우선함)
- 매수/매도의 green_count·금/은비율 임계값은 모두 화면에서 자유롭게 조정 가능
- green_count 신호의 체결가는 신호 발생일 기준, 고급 설정에서 지정한 지연일수만큼 지난 뒤
  첫 거래일 종가(기본값 0일 = 신호 당일 즉시 체결). 예: 매수 지연일수를 30으로 설정하면
  "신호 조건 충족 후 약 1개월 뒤 매수"를 시뮬레이션. 금/은비율·재진입 신호에는 지연이
  적용되지 않음
- **검증: 재진입 로직 효과 비교** 섹션(거래 내역 표 아래)에서 (1) 2025년 구간을 재진입 로직
  적용 전/후로 나눠 매매 타이밍(거래 내역)과 수익률을 비교하고, (2) 단기 재진입 빈도 제한
  ON/OFF에 따른 전체 분석 기간의 매매횟수·승률·누적수익률·CAGR을 비교합니다. 두 비교 모두
  현재 화면의 다른 설정(매수·매도 조건, 지연일수 등)은 그대로 유지한 채 재진입 관련 옵션만
  달리 적용한 결과입니다
- 고급 설정의 **매수 후 최소 보유일수**(역일/달력일 기준 — 주말·공휴일 관계없이 매수일로부터의
  날짜 차이 `date2 - date1`로 계산)를 설정하면, 매수 후 그 일수가 지나기 전까지는 어떤 매도
  조건도 확인하지 않고 무조건 보유합니다(단기 매매가 아닌 최소 보유 기간을 둔 전략용, 기본값
  30일 = 약 1개월; 0일로 낮추면 제한 없음)
- 고급 설정의 **상승추세 중 매도신호 노이즈 필터** (기본값 ON, 매수 쪽 재진입 로직과는 완전히
  별개의 로직)는 green_count·금/은비율 매도 신호가 실제로 체결되기 직전에 개입합니다. 그날(D0)
  종가가 200일 이동평균보다 `DEFAULT_SELL_NOISE_FILTER_BUFFER_PCT`(기본 5%) 이상 높을 때만
  작동하며(미만이면 이 필터 없이 항상 그대로 즉시 매도), 매도 실행 여부는 **오직**
  D0+`SELL_NOISE_FILTER_WINDOW_DAYS`(기본 7)일(역일 기준) 시점의 종가를 D0 종가와 비교한
  결과만으로 결정됩니다 — 낮으면 그날 매도를 실행하고, 낮지 않으면 관찰모드를 해제하고 D0의
  신호는 없었던 것으로 처리합니다(이후 새 매도신호부터 다시 처음부터 시작). D0~D0+7일 사이에
  추가로 뜨는 매도신호는 매도 여부에 전혀 영향을 주지 않으며, 몇 번 더 떴는지·다음날 재발생
  (2연속) 여부·7일 내 `SELL_NOISE_FILTER_REFERENCE_OCCURRENCE_THRESHOLD`(기본 3)회 이상
  여부는 순수 참고 기록으로만 남아 검증 섹션에 표시됩니다. 이 필터로 매도가 실행된 거래는
  거래 내역의 매도 사유에 "(노이즈필터: ...)"가 덧붙어 표시됩니다. 끄면 이 로직 도입 이전과
  동일하게 매도신호 발생 즉시 항상 매도합니다.
- 고급 설정의 **KRX 금현물 보유 수수료 (연, %)** (기본값
  `DEFAULT_KRX_HOLDING_FEE_ANNUAL_PCT` = 0.15%, ② KRX 금현물 선택 시에만 적용되고 조정
  가능)는 보유 중인 기간의 경과 일수에 비례해 연복리로(`(1 - 수수료%/100) ** (경과일/365.25)`)
  수익률에서 차감됩니다. Buy & Hold(분석 기간 내내 보유)와 신호전략의 보유 기간 모두 동일하게
  적용되며, ① 국제 금 시세(실물이 아닌 참고 가격)에는 적용되지 않습니다.
- 신호전략의 CAGR은 실제 보유 기간의 일수만 분모로 사용(현금 보유 기간 제외); Buy & Hold의
  CAGR은 위에서 설정한 전체 분석 기간 기준
- **요약 지표는 4개 그룹으로 묶여 있습니다** (최대 낙폭(MDD)은 어느 그룹에도 넣지 않고
  삭제했습니다):
  - **① 매매 개요**: 매매횟수, 보유기간 비중, 승률
  - **② Buy & Hold**: 누적수익률, CAGR
  - **③ 신호전략 (보유기간)**: 누적수익률·CAGR 모두 보유 기간에만 투자했다고 가정한 값
    (미보유 기간은 반영하지 않음)
  - **④ 신호전략 (미보유기간 기회수익률 포함)**: 보유 기간엔 실제 금 수익률을, 미보유
    기간엔 이 그룹 안의 "기회수익률(연, %)" 입력값(기본값 10%, 예: 채권 매입 가정 —
    바로 재계산 가능)을 이어붙인 전체 분석기간 기준 누적수익률·CAGR. ③과 나란히 비교하면
    미보유기간을 그냥 현금(0%)으로 두는 대신 다른 자산에 투자했다고 가정했을 때의 차이를,
    ①의 "보유기간" 비중과 함께 보면 그 차이가 어디서 오는지 가늠할 수 있습니다. 매수·매도
    전환일의 귀속 방식은 `run_backtest()`가 실제로 체결하는 방식(매수일 당일은 무수익,
    매도일 당일은 금 수익률 전부 반영)과 동일하게 맞춰, 기회수익률 0%일 때 이 지표가 ③의
    누적수익률과 정확히 일치하도록 검증됨
- 누적수익률 차트에는 매수(▲ 파란색)·매도(▼ 빨간색) 시점이 표시되며, 연도별 수익률은 부분연도도
  비교 가능하도록 해당 연도 실제 일수 기준으로 연환산해서 보여줍니다
- 거래 내역 표와 차트 마커 툴팁에 각 매수/매도를 유발한 조건(사유)이 함께 표시됩니다
- **상승추세 중 매도신호 노이즈 필터 ON vs OFF 비교** 접기(거래 내역 표 아래)에서 현재 화면의
  나머지 설정(보유 수수료 포함)은 그대로 둔 채 이 필터만 ON/OFF로 각각 계산해 매매횟수·승률·
  MDD·Buy&Hold/신호전략(보유기간)/신호전략(미보유기간 기회수익률 포함) 각각의 누적수익률·
  CAGR을 비교하고, 관찰모드가 발동된 사례를 "가격 하락으로 매도됨"과 "하락 없어 해제됨"으로
  나눠 각각 몇 건인지, D0/D0+7일 종가와 참고 기록(발생 횟수·2연속 여부·7일 내 3회 이상 여부)을
  대표 날짜와 함께 보여줍니다

과거 데이터 기반 시뮬레이션으로 미래 성과를 보장하지 않으며, 거래비용·세금·슬리피지는
반영되지 않았고 표본 기간이 짧아 과최적화(overfitting) 위험이 있습니다.

## 금 가격 기준 (국제 시세 vs KRX 금현물)

"유효성 검증" 페이지 상단(대시보드 페이지에도 동일하게 노출)의 **"금 가격 기준"** 라디오
버튼으로 백테스트 전체가 사용하는 금 가격을 고를 수 있습니다:

- **① 국제 금 시세 (USD/oz, GC=F)** — 이 옵션이 도입되기 전과 동일하게 작동합니다.
- **② KRX 금현물 (KRW/g, 실제 국내 시세)** — 기본값. 환율을 곱한 환산값이 아니라, KRX 금현물시장
  (종목코드 `04020000`, "금 99.99_1kg")의 실제 국내 시세를 그대로 사용합니다. 이 값은
  Naver의 주식 데이터 API(`api.stock.naver.com/marketindex/metals/M04020000/prices`,
  `M` + KRX 코드)에서 가져옵니다 — `data.krx.co.kr` 자체의 조회 API는 로그인 세션이 필요해
  익명 접근이 막혀 있어, 로그인 없이도 KRX 공식 시세를 그대로 미러링하는 이 경로를
  사용합니다(`gold_dashboard/data_sources.py`의 `fetch_krx_gold_krw_per_gram`). 페이지당
  최대 60건까지 응답하는 API를 뒤로 페이징하며 전체 히스토리(시장 개장일인 2014-03-24부터
  오늘까지)를 모아 오고, 요청 실패 시 페이지별로 최대 3회까지 5~10초 지수 백오프로 재시도한
  뒤 실패하면 화면에 에러 메시지로 표시합니다. 이 전체 히스토리 fetch는
  `st.cache_data(ttl=3600)`으로 캐시되어, 캐시가 살아있는 동안은 다시 요청하지 않습니다.

**②를 선택하면** 이동평균(5/30/60/200일)·장기추세 필터(버퍼+기울기)·단기 재돌파
트리거·green_count 판정용 이평선과 무관한 매수·매도 신호 발생 시점 자체·백테스트 전체
(거래 내역·매매횟수·보유기간 비중·승률·MDD·Buy&Hold/신호전략(보유기간)/신호전략(미보유기간
기회수익률 포함) 각각의 누적수익률·CAGR)·누적수익률과 CAGR 비교 그래프까지, 이 페이지의
전체 계산이 KRX 금현물 가격 기준으로 다시 이뤄집니다. **금/은비율만은 예외**로, 이 선택과
무관하게 항상 국제 금·은 시세(GC=F/SI=F, USD/oz)로 고정 계산됩니다 — KRW/g 금 가격을
USD/oz 은 가격으로 나누면 의미 없는 숫자가 되고, 대시보드 표의 금/은비율 행도 이 선택과
무관하게 항상 국제 시세 기준이기 때문입니다(`gold_dashboard/timeseries.py`의
`fetch_backtest_frame`이 `gold`(선택된 기준)와 `gold_intl`(항상 GC=F) 두 컬럼을 함께
반환하고, `gold_dashboard/backtest.py`의 `compute_signals`가 비율 계산에는 반드시
`gold_intl`을 사용).

이 라디오 버튼은 대시보드 페이지와 유효성 검증 페이지가 세션 상태 하나를 공유하므로 한쪽에서
바꾸면 다른 쪽에도 그대로 반영됩니다. 다만 **대시보드 페이지 자체의 표(실질금리·달러인덱스·
금/은비율·WTI·VIX)와 지표별 시계열 그래프는 이 선택과 무관하게 항상 국제 시세 기준**입니다 —
②를 선택하면 그 표 위에 이 사실을 알려주는 안내 문구가 추가로 표시됩니다.

KRX 금현물시장은 2014-03-24에 개장했으므로, ②를 선택한 상태에서 분석 기간(+이동평균 계산용
버퍼)이 그 이전으로 거슬러 올라가면 시작일이 자동으로 2014-03-24로 조정되며, 화면에 안내
메시지가 표시됩니다.

거래 내역 표·차트 툴팁의 가격 표시도 기준에 맞춰 자동으로 바뀝니다(① `$1,234.56` 형식,
② `123,456원` 형식, 소수점 없음).

"검증: 재진입 로직 효과 비교" 섹션 아래의 **"금 가격 기준 (① 국제 시세 vs ② KRX 금현물)
비교"** 접기 안의 버튼을 누르면, 현재 화면의 나머지 설정(매수·매도 조건, 고급 설정)은 그대로
둔 채 ①/② 두 기준 모두로 각각 계산해 매매횟수·승률·MDD·Buy&Hold/신호전략(보유기간)/
신호전략(미보유기간 기회수익률 포함) 각각의 누적수익률·CAGR을 나란히 비교하고, 두 기준에서
매수·매도가 발생한 날짜 집합의 차이(한쪽에만 존재하는 날짜)를 구체적으로 나열해 보여줍니다.
② 쪽 데이터가 아직 캐시되지 않았다면 이 버튼을 누른 시점에 최초 수집이 이뤄져 1분 내외
걸릴 수 있습니다.

## 갱신 주기

데이터 소스가 모두 일봉(전일 확정 종가) 기준이라 "실시간"이 아니라 **매일 아침 7시(KST)에
전일 미국장 마감 종가로 자동 갱신**됩니다. GitHub Actions가 매일 22:00 UTC(=07:00 KST)에
`gold_dashboard/update_data.py`를 실행해 `data/latest.json`을 갱신·커밋하고, Streamlit
앱은 이 파일을 읽어 즉시 표시합니다(파일이 없으면 그때그때 실시간으로 계산).

앱이 "오늘"을 계산할 때는 반드시 `gold_dashboard/timeutil.py`의 `today_kst()`를 사용합니다
(파이썬 기본 `date.today()`는 호스팅 서버의 로컬 시간대를 따르는데, Streamlit Cloud 등
대부분의 서버는 UTC라서 KST보다 최대 하루 늦게 날짜가 바뀝니다 — 예: KST 오전 7~8시는 아직
UTC로는 전날이라, `date.today()`를 그대로 쓰면 기준일 선택 캘린더가 오늘 날짜를 하루 늦게
표시/제한하는 문제가 생깁니다). 새 코드에서 "오늘 날짜"가 필요하면 `date.today()` 대신
`today_kst()`를 사용하세요.

## 기준일 선택

화면 상단의 "기준일 선택" 날짜 입력으로 원하는 과거 날짜를 고를 수 있습니다.

- **오늘 날짜(기본값)**: `data/latest.json` 캐시를 읽어 즉시 표시됩니다.
- **과거 날짜**: 매일 갱신되는 캐시가 아니라 그 시점 그때그때 실시간으로 계산됩니다
  (각 지표를 해당 날짜 이전 약 2년 구간으로 다시 조회 후 이동평균/돌파지속 일수를 재계산).
  네트워크 접속과 `FRED_API_KEY`가 필요하며, 선택한 날짜가 주말·휴장일이면 그 직전
  거래일 종가가 자동으로 표시됩니다.

## 지표별 시계열 그래프

메인 표 바로 아래, 지표별로 "그래프 보기" 버튼이 있습니다. 누른 지표만 그 시점에 최근 10년치
(고정값, 조정 불가 — 유효성 검증 페이지의 분석 기간 설정과 무관) 데이터를 받아와 그립니다 —
페이지를 열었을 때나 다른 지표 버튼을 눌렀을 때는 계산이 실행되지 않습니다(`st.session_state`로
지표별 펼침 여부를 따로 관리하고, 그 플래그가 켜진 지표에 대해서만 데이터를 요청하는 조건부
실행 패턴). 데이터는 하루(TTL 86400초) 캐시됩니다.

- 실질금리·달러인덱스·WTI·VIX: 해당 지표의 일별 종가 + 5/30/60일 이동평균(옅어질수록 장기)
  + 비교용 금(GC=F) 가격을 이중 y축(왼쪽 = 지표, 오른쪽 = 금 가격 $)으로 표시
- 금/은비율: 이동평균 대신 원래 값 + 기준선(학술적 관행값 80, 유효성 검증 페이지의 매도신호
  임계값 기본값 60 — `config.DEFAULT_GS_RATIO_SELL_THRESHOLD`) 수평선 + 금 가격
- x축은 두 페이지의 시계열 그래프(이 그래프들과 유효성 검증 페이지의 누적수익률 차트) 모두
  월 단위가 아닌 연도만(`%Y`) 표시되도록 축 포맷과 tick 간격을 맞춰뒀습니다
- fetch 로직은 `gold_dashboard/timeseries.py`에 공통 모듈로 분리되어 있으며, 백테스트
  페이지(`backtest.py`)와 메인 페이지(`app.py`)가 이 모듈을 함께 사용합니다(중복 구현 없음).
  각 fetch 함수는 `years` 인자를 받으며, 메인 대시보드는 항상 고정값(10)을, 백테스트 페이지는
  자신의 조정 가능한 분석 기간 값을 넘겨 서로 독립적으로 동작합니다
- 배경 세로 음영(옅은 빨강) = 그 지표 기준 매수신호 활성 구간이며, **실제 매수·매도 신호에
  쓰이는 지표에서만** 표시됩니다:
  - 실질금리·달러인덱스: 5/30/60일 이평선 3개를 모두 동시에 만족하는 날 (green_count에 쓰임)
  - 금/은비율: 값이 매수 임계값(기본 100, `config.DEFAULT_GS_RATIO_BUY_THRESHOLD`) 이상인
    날 — 이동평균과는 무관한 순수 종가 기준 임계값 비교
  - **WTI·VIX는 음영 표시가 없습니다** — 참고용 지표일 뿐 실제 매수·매도 트리거에 쓰이지
    않으므로, 자체적으로 이평선을 돌파하는 것처럼 보여도 매매 신호로 취급하지 않습니다
  - 실질금리·달러인덱스·금/은비율의 판정은 `gold_dashboard/signals.py`의 단일 함수
    (`gold_friendly_vs_ma`/`ratio_threshold_active`)를 통해 이뤄지며, 메인 표의 셀
    하이라이트(`build_table.py`)·백테스트의 green_count/금/은비율 계산(`backtest.py`)도
    전부 같은 함수를 호출합니다 — 이평선 하회/상회 판정 코드가 여러 곳에 따로 구현되어
    있지 않습니다
  - green_count는 실질금리+달러인덱스 두 지표의 판정을 **합산**한 값(0~6)이며, 기본 매수
    임계값이 6(만점)이라 green_count 트리거로 매수가 발생하는 시점에는 두 지표 모두 3/3을
    만족한 상태입니다 — 즉 그 시점에는 실질금리·달러인덱스 그래프 모두에 음영이 표시됩니다
    (임계값을 6 미만으로 낮추면 다시 두 지표 중 한쪽만 음영이 뜨는 경우가 생길 수 있습니다).
    금/은비율 단독 트리거로 발생한 매수는 애초에 실질금리·달러인덱스 조건과
    무관하므로 두 그래프의 음영과 겹치지 않는 것이 정상입니다

## 돌파지속 일수 로직

각 지표의 종가가 해당 이동평균선(5/30/60일)을 상향 돌파한 뒤 계속 그 위에 머물러 있는
일수를 센 값입니다. 종가가 이평선 아래로 다시 내려가면 즉시 0으로 리셋됩니다. 세 이평선은
각각 독립적으로 계산되며, 돌파 중인 셀은 옅은 녹색 배경으로 표시됩니다.
